# 暗牌 21 · 精致牌桌版 v0.3.0

中文单人 21 点小游戏，包含经典 S17 庄家、策略庄家，以及可开关、默认关闭的赛后复盘教练。纯 TypeScript / React 19.2.6 / Vite，适合之后接入现有 React/Vinext 网站。

没有真实金钱、下注、筹码、充值、支付或天然 21 的额外奖金。未修改或发布任何现有网站。

## 立即试玩

用现代浏览器打开 `暗牌21.html`。JS、CSS、牌面和教练 Worker 源码均已内联，不需要 Node.js、CDN、外部字体或网络资源。

**验证边界：** 已在 jsdom 中运行实际生产 HTML，通过 Node worker_threads 执行文件中真正内联的教练 Worker，完成两种模式的发牌、停牌、结算和复盘；Blob URL 创建/撤销一致，外部资源为 0。这是程序化功能冒烟验证，不是浏览器视觉或 file:// 验证。本次重新尝试真实浏览器：Chromium 因进程 socket 权限受限无法启动；独立云浏览器无法连通当前工作区本地预览，也无可用文件预览路线。因此真实浏览器视觉、触屏、音频与 file:// Worker 支持尚未实测，未提供截图。

若浏览器不允许本地文件存储，仍可玩，但记录不会跨页面保留；若阻止 Blob Worker，教练会明确提示失败，游戏不受影响。接入网站时若 CSP 禁止 Blob Worker，应由网站维护者批准对应支持方案，不要随意放宽安全策略。

## 开发与构建

要求 Node.js 22.12+（本次使用 24.19.0）。所有依赖精确锁定，附 package-lock.json。

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build:portable
npm run test:portable
npm run benchmark
```

- `npm run dev`：独立开发页，默认 http://localhost:5173。
- `npm run build`：常规静态网站输出到 dist/。
- `npm run build:portable`：同时生成独立的 `暗牌21.html`。
- `npm run test:portable`：对已生成的 HTML 运行 jsdom + Node worker_threads 冒烟测试。
- `npm run benchmark`：重跑有限牌堆求解器测试样例和策略庄家组合性能数据。
- dev/test/build 前自动重新生成 `src/coachWorkerSource.ts`；它是由 coach.worker.ts 和 solver.ts 打包得到的内联源码。不要手改这个生成文件。
- Vite 独立客户端构建可能提示忽略 `use client` 指令；构建会成功，该指令为后续客户端组件集成保留。

## 这一版的交互升级

- 深绿色绒面、双层桌沿、纸质牌面与纹理牌背，全部由本地 CSS 绘制，无图片、字体或引擎依赖。
- 逐张发牌、暗牌 3D 翻面、轻量状态过渡和结算高亮。发牌间隔 250ms，玩家输入保护 360ms，庄家行动间隔 650ms；动画不承担规则结算，连续点击不会重复出牌。
- 五步流程条明确「准备 → 发牌 → 你来决定 → 庄家行动 → 本局结果」。按钮直写「要牌 / 再拿一张」「停牌 / 保留点数」。没有倒计时或迫使操作的动效。
- 玩法说明采用可关闭对话框，支持 Escape、焦点循环和触发按钮焦点恢复。操作后仍保留组件内键盘控制。
- 复盘步骤高亮，EV 数字与同尺度条形同时展示。条形范围为 −1 到 +1，中线为 0；仅方便比较，数字为准。收起复盘也会取消当前计算，重新打开可复用已完成结果。
- 小屏手牌横向滚动，不换行撑高桌面；发新牌自动移至末张。手牌区域可聚焦并使用浏览器的横向滚动，触屏可左右滑动。
- 系统「减少动态效果」会关闭所有过渡与动画；音效仍默认关闭。两种模式、教练的信息边界及分模式统计保持一致。

## 两种模式

### 经典 21 点

玩家先完成要牌/停牌，然后庄家翻开暗牌并按固定规则行动：不到 17 必须要牌，所有 17 或更高必须停牌，包括 A+6 的软 17（S17）。

### 策略庄家

玩家仍先完成行动。庄家看到自己的手牌和玩家最终手牌后，选择最大化自身预期得分的要牌/停牌动作：胜 +1、平 0、负 −1。

庄家具有后手和已知玩家终值的信息优势，这是有意设计的难度模式，不是对称公平对决。它只能知道剩余牌的点数数量，不能读取未来牌序，也不能改变牌序。实际庄家使用不设近似上限的有限牌堆精确递推，使实际策略与精确教练模型一致；已知目标后的状态空间很小。

模式只能在开局前或一局结束后切换。两模式分别统计胜、负、平和积分。

## 共同规则

1. 每局重新洗匀一副 52 张牌，固定初始发牌顺序：玩家、庄家、玩家、庄家。无大小王。
2. 2–10 依牌面计分；J/Q/K 为 10；A 自动取 1 或 11 的最佳值。
3. 玩家看自己的所有牌，庄家起手一明一暗。初始四张发完立即检查天然 21：双方天然平局、单方天然获胜并揭牌结算。
4. 玩家要牌爆牌立即输；停牌或达到 21 后庄家翻牌并行动。庄家爆牌玩家胜；否则点数高者胜、同点平局。
5. 后续凑成的 21 不是天然。所有胜局都只计 +1，不模拟赌注或 3:2 支付。
6. 本版只实现 hit/stand（要牌/停牌），没有分牌、加倍、保险或投降。不能直接套用包含这些动作的赌场基本策略表。

## 教练：主要用于赛后复盘

- 默认关闭，可随时开关；游戏过程中不提供推荐，不抢先透露信息。
- 每次玩家决策前只保存当时的玩家手牌、庄家明牌、模式和已排除天然的检查结果；不保存暗牌、真实牌堆、未来顺序或随机种子。
- 开启教练后，结束一局再点「复盘本局」，按步骤查看原来的选择、建议、要牌/停牌预期得分、下一张爆牌概率和预计得分差。
- 预期得分是胜 +1 / 平 0 / 负 −1 下的每局效用，不是赢牌概率；0.03 的差距不代表本局实际少赢了 0.03 分。
- 赢了不一定打得合理，输了也不一定打错；教练按当时的信息评估，不用后来翻出的牌作事后判断。
- 「精确计算 · 有限单副牌」：针对当前简化规则、所选庄家策略和当时信息集，对未来要牌/停牌完整求解。
- 「近似建议 · 独立抽牌模型」：精确计算超出预算时，丢弃未完成结果，重新完整求解独立有放回模型。全部 EV、差距和爆牌概率都来自该替代模型；策略模式还近似了庄家策略。不能称为实际单副牌的理论最优。
- 教练在独立 Worker 中计算；选择其他步骤、关闭教练、切模式、新局或卸载会取消旧任务。处理结果时拒绝过期消息，正确撤销 Blob URL，防止提前取消造成泄漏。
- 初始天然结算的局没有玩家选择，无需动作复盘。

算法、暗牌后验、Bellman 递推与限制见 `SOLVER-NOTES.md`。精确结果的理论最优范围仅是此处明确规则/信息集/动作集合，不是所有 Blackjack 玩法，也不保证任何一局获胜。

## 性能与验证

- 原有 59 项测试全部通过，并新增独立交互回归；完整数量及覆盖范围见 `qa/VERIFICATION.md`。
- TypeScript、生产构建、离线打包通过。
- 独立小牌堆逐排列 oracle 校验两种模式的精确 EV；覆盖否定天然后验、多 A、重复牌点、耗尽、天然、隐藏字段不变性与强制近似回退。
- 一次云端 Node 基准中，18 个教练样例均在 150,000 节点 / 1,200ms 预算内精确完成，最大 107,613 节点、约 462ms。含低软牌等更复杂案例，但不是所有局面的保证。
- 策略庄家 990 个两张起手/目标组合均精确完成，最大 743 节点；该次最慢约 7ms。
- 原始数据：`solver-benchmark-results.json`；便携验证：`qa/portable-smoke-results.json`。上述时间不是移动浏览器性能保证。
- 真实浏览器/视觉/file:// 限制见文首及 `qa/VERIFICATION.md`。

## 操作与生命周期

H 要牌、S 停牌、N 新局；按钮支持触控。状态机与短输入锁防止同一步双击、重复或冲突快捷键；新局锁也避免快速重复启动。对话框打开时游戏快捷键不执行。音效默认关闭，开启后为本地合成短音。尊重系统减少动态效果偏好。

切到后台时暂停后续发牌和庄家定时行动，回来后需点「继续对局」，没有倒计时。赛后复盘是无时间压力的独立计算，可手动取消。刷新、退出或卸载中止未完成局，不计战绩；不恢复未完成局。卸载清理定时器、事件监听、音频上下文和 Worker。

localStorage 使用 `twenty-one:v2`，保存分模式战绩、音效、教练开关和上次模式。旧 simultaneous 版本的 v1 记录保留为 legacy 数据，不混入两种新玩法；不删除旧键。损坏数据/存储拒绝/配额不足安全降级。跨标签页合并不是本版功能。重置只清空当前模式，需要确认，对局中不可执行。

## 接入 React / TS / Vinext 网站

复制 src/ 中非测试源码（包括生成的 coachWorkerSource.ts）到现有网站组件目录。无需专用 Vite 插件，Worker 源码已作为普通字符串模块包含。

**复用宿主的 React 19.2.6，不安装第二份 React，不把独立 main.tsx 或 dist 的 React 包当子组件加载。** 建议客户端挂载，避免持久化状态导致 SSR 首屏不一致。BlackjackGame.tsx 已带 `use client`。

```tsx
import { BlackjackGame } from './games/strategy21/BlackjackGame';

export function GameRoom() {
  return <BlackjackGame
    persist={true}
    onExit={() => navigate('/games')}
    onRoundEnd={(result) => console.log(result)}
  />;
}
```

navigate 由现有网站路由提供；例子不依赖具体路由库。

```ts
type RoundResult = {
  round: number;
  mode: 'classic' | 'strategic';
  outcome: 'win' | 'loss' | 'tie';
  reason: string;
  playerTotal: number;
  opponentTotal: number;
};
type BlackjackGameProps = {
  onRoundEnd?: (result: RoundResult) => void;
  onExit?: () => void;
  persist?: boolean;          // 默认 true
  className?: string;
  globalKeyboard?: boolean; // 默认 false，仅组件焦点内响应
};
```

- 回调仅完整结算时触发一次；宿主自行处理回调异常。
- onExit 不自动路由，宿主负责导航和卸载；更换 React key 可重新创建牌桌实例。
- CSS 类均以 bj- 开头，可覆盖 .bj-app 的 padding/min-height；无全局 body 样式。
- 建议一页只挂一个牌桌，固定 ARIA 对话框 ID 和持久化键按单实例设计。
- 更新 solver.ts 后，运行 scripts/build-coach-worker.mjs 重新生成 Worker 字符串，再复制更新文件。
- 如果宿主 CSP 不接受 Blob Worker，保持游戏可运行并显示教练不可用，交由网站维护者决定部署支持方式。
- 单机游戏全部状态可被开发者工具检查；这里的公平性是决策接口的信息边界，不是联网反作弊或密码学隐藏。
